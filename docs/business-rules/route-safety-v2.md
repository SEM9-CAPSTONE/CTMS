# Route Safety v2 Business Rules

Effective change: 2026-10-29. Source: `CTMS_Route_Safety_Spec_v2.docx`, supplied for implementation. This supplement governs CTMS-010 safety analysis and its consumers; it does not change the reporting actor or workflow of CTMS-049, the DRAFT restriction of CTMS-014, or the approval/closure policies of other stories.

User-requested amendment, 2026-10-30: fetch current NCHMF warnings during Host analysis. This supersedes the earlier stored-only ingestion choice.

## CTMS-052 consumer boundary — 2026-11-06

BR-473/474/476/477/479/480 retain their preview meaning. Package eligibility is stricter: only normalized GOVERNMENT evidence with source validity or FIELD_VERIFIED evidence with an independent authorized Host decision is eligible. HOST_DEFINED remains a preview source; resolved/closed is not verification. A package source adapter must preserve complete run availability, exact versions, spatial scope and validity. Interactive preview or an empty feature table cannot prove a successful no-alert check. This adds a consumer contract and does not replace existing preview rules. See `file/spec/ctms-52-upstream-safety-contracts.md` for proposed upstream tasks.

## Rule changes

| Rule | Decision | Current wording |
| --- | --- | --- |
| BR-027 | Clarify the implemented route contract | A Route belongs to `host_id`. It stores name, optional description, a valid non-zero WGS84 LineString, computed positive `length_meters`, difficulty, positive Host-entered `expected_duration_minutes`, status and timestamps. Start and finish are derived from the first and last coordinates. Creation produces an internal DRAFT route. Route Safety does not introduce mandatory persisted start/end fields, route version or porter-required flags. |
| BR-172 and BR-202 | Retain | Backend role/ownership remains authoritative. An active Route remains an internal operational resource and gains no Camper browse/detail access. |
| BR-191 and BR-212 | Retain | Critical changes remain auditable; implementation, specification, test cases and data documentation change together. |
| CTMS-014 rules | Retain | Host-defined danger zones keep ownership, DRAFT-only creation, validation and audit behavior. |
| CTMS-049 rules | Retain | Assigned Porter remains the incident reporter. Safety reads existing incident identity, location and authoritative status without creating a duplicate observation or new lifecycle. |

The older CTMS-010 specification's generated BR-027 wording and its exclusion of automatic safety analysis are superseded by this revision. External ingestion is separate from Host danger-zone creation and never writes those records automatically.

## Configured defaults

Point proximity 300 m (plus a saved Point zone's radius when checking its area), current-data fallback age 360 minutes, field-incident fallback age 1440 minutes, preview debounce 500 ms, UI refresh 60 seconds. Saved Polygon zones within that proximity also participate, including intersecting zones. These defaults are technical policy choices, not provider guarantees. Provider `validUntil` is not replaced with a fallback age or fetch timestamp. A historical source classification cannot be promoted merely by re-importing it.

## Nearby saved zones while drawing — 2026-11-16

User-approved amendment to CTMS-010 and BR-477: a Host planning a new route should see nearby hazards already recorded on their other routes before departure. The same read scope applies to unsaved edits. This replaces the earlier selected-route-only merge restriction, not route ownership or another Host's privacy boundary. Existing shared external evidence remains available; this change does not publish private Host zones or infer Admin verification from their mere presence in route_danger_zones. When the same saved zone is supplied through both persisted-route data and safety analysis, render one marker. Marker/detail-panel clicks must not add or move route vertices; polygon drawing remains available in editing mode. The subsequent shared published-danger amendment below adds viewport collection for Admin-published hazards only.

## Automatically visible Admin-published danger zones — 2026-11-16

This later user-requested amendment extends BR-475/477 with a shared viewport layer and supersedes the earlier exclusion of viewport collection. Authenticated Host, Admin, Camper and Porter web users see published danger zones as soon as they open a route map: route creation with zero vertices, preview, checkpoint maps, Trip planning and operational Trip maps. No selected Route, Trip, booking, assignment or nearby drawn line is required. Pan/zoom loads the visible area after 250 ms; an open map refreshes every 15 seconds and on window focus. These defaults do not promise real-time Admin decision delivery.

Publication requires an authorized Admin's applied ADD_HAZARD_AREA or UPDATE_HAZARD_AREA corrective action under CTMS-118, based on current CONFIRMED evidence under CTMS-117. CONFIRMED alone, NO_DATA_CHANGE, OTHER and checkpoint instruction corrections do not publish hazards. The authoritative geometry, severity, description and radius must match the most recent applied hazard decision, with the same confirmed review and evidence. Rejected/reopened or changed evidence and subsequent unapproved edits are excluded on the next successful refresh. A Host report or record existence does not imply approval.

Published features carry ADMIN_VERIFIED / VERIFIED, severity, geometry, description, radius and last update. They remain active until publication is withdrawn or invalidated; the weather observation TTL does not expire them. The projection omits private route names, owner/member data, review reasons and evidence. Reading public safety facts grants no access to another Host's route detail or editing. Unpublished own-Host zones retain geometry-based BR-477 proximity and UNVERIFIED status; another Host's unpublished zones remain private. Route analysis includes spatially relevant published hazards once per zone.

GET /api/route-safety/verified-zones accepts ordered west/south/east/north bounds in EPSG:4326 and returns a canonical FeatureCollection, generatedAt and truncated. Authentication is required. It returns at most 500 records without external provider calls. Whole-world fallback and wrapped native viewports use a bounded whole-world read. Truncation asks the user to zoom in. Cache keys include actor and viewport; obsolete requests are aborted. Read failures offer retry without blocking editing.

Render one marker when the same hazard also arrives from persisted route data or analysis. Markers have a 44 px hit area; published polygons also provide an interior marker. Marker/details clicks cannot add or move route vertices, checkpoints or the meeting point. Polygon area clicks open details in viewing mode; editing retains drawing gestures and uses the marker for details. Fallback maps show the same details in a panel.

CTMS-014 writes, DRAFT restrictions, review/correction authorization, route approval, closure, automatic Trip risk and offline package eligibility are unchanged. Camper mobile and offline packages remain outside this web display amendment. No new seed accounts or copied runtime hazards are required.

## Production source enablement

NCHMF live collection is enabled by default through server-side configuration. Each valid Host analysis contacts the public warning source and retrieves administrative geometries for the route area; there is no provider request for an unauthorized/invalid route. The source may publish on an hourly cycle, so its original forecast time and six-hour validity are shown rather than implying publication at the moment of drawing. Empty, disabled, unavailable and partial collection states are explicit. Source failure cannot turn old imported warnings into current evidence. Controlled Admin import and its configured source/permission rules remain unchanged for the separate stored-data workflow. VNDMS event search is collected in parallel, preserving ended/ongoing state and representative coordinates. OpenStreetMap supplies nearby mapped water in a separate unverified group. Each provider has its own source status.

User-confirmed scope, 2026-10-30: the route preview includes dangerous areas, nearby dangerous/event points and nearby water. Live points, lines and polygons are filtered by meter distance to the entire route. Historical/ended events remain labeled context; mapped water has no implied current availability or potability. VNDMS risk levels are preserved without inventing CTMS severity.

Scope clarification, 2026-10-30: Route supplies reusable geometry with automatic nearby hazard and water context. Route creation/editing/submission/approval neither requires nor generates start/finish checkpoints or waypoints. Those belong to Trip planning, whose refactor is deferred. Existing ownership and lifecycle restrictions still apply.
